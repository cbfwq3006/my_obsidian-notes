如果你第一次读到这个号，可以这么认识我们：YouCore不做知识付费，只做能力升级。

你让 WorkBuddy 帮你去订房网站找性价比最高的民宿，或者去 B 站给一批 AI 视频挨个点赞。

它接下任务，然后开始“从零摸索”。

这个过程你大概率见过：在几个页面之间来回横跳，陷进死循环；搜着搜着偏离了最初的意图；明明快接近答案了，却提前收手、草草交差。

更让你窝火的是另一件事：**好不容易摸索通了，这点经验却随这一轮对话一起蒸发。** 下次换个任务、换个 Agent，它又从零开始，把你踩过的坑再踩一遍。

你想把这次操作“教”给它：

◆ 写提示词？一次两次还行，操作一长就描述不清。

◆ 装现成的 Skill？通用 Skill 和你具体的操作流程，总有那么点出入。

◆ 自己用 Skill-creator 写一个？会话里干扰信息太多，需求天马行空，执行的质量时好时坏。

**有没有一种方法：不用写提示词，不用描述流程，你亲手在浏览器里把操作做一遍，它就自动学成一个 Skill？**

有。就是今天要说的 Browser-BC。

01

这个工具做了什么？

Browser-BC 是 Einsia AI 旗下 Navers Lab 开源的一个「浏览器行为克隆」工具，开源地址：`github.com/Einsia/Browser-BC`。

一句话说清楚：**你亲手在浏览器里把任务做一遍，它录下你的操作轨迹，自动蒸馏成一份自然语言的 Skill，从此 Agent 照着就能跑通同类任务。**

它很像“agentic 时代的按键精灵”，但和传统按键精灵有本质区别。

传统按键精灵录的是坐标和按键序列：点 (x1,y1)、输入“xxx”、点 (x2,y2)。页面布局一改，整段脚本立刻作废。

Browser-BC 录的不是坐标，是**语义级说明书**：

传统按键精灵：点 (x1,y1)，输入“xxx”，点 (x2,y2)

Browser-BC：在搜索框填入关键词，回车，等列表加载后逐条点开，对每个视频点“点赞”，直到页面出现“已点赞”状态

它只保留「该做什么、怎么判断进展、怎么算完成」，剥离掉精确坐标、DOM 选择器、临时 ID、登录态这些一碰就碎的脆弱细节。**页面布局怎么变，它都能举一反三。**

在后台，它的工作流是四步：**操作轨迹记录 → 能力提取 → 能力归桶 → 技能生成**。

![[00 临时箱/images/00743435c10d9e020c1e8222f81afb56_MD5.png]]

最值钱的一点是：**蒸馏和执行可以分开。**

一次用强模型蒸馏好的技能，交给小模型、便宜模型也能执行。研究团队在真实网站上验证：注入 Browser-BC 技能后，Agent 的任务成功率从 32.9% 提升到 68.4%，几乎翻倍。

02

安装方法

安装不用你手动下载配置，把下面这句话发给 WorkBuddy 就行：

请帮我安装 Browser-BC 工具，源代码在 https://github.com/Einsia/Browser-BC，装好后验证一下能否运行。

WorkBuddy 会自动完成下载、安装。成功后，你的桌面会多出一个叫 **JourneyForge-Local** 的工具文件夹。

接下来还有两步配置：

## 第一步：接入模型 API

Browser-BC 的蒸馏环节要单独对接一个大模型。把你已有的模型 API 信息（比如 DeepSeek 开放平台买的 API，模型选 `deepseek-v4-flash`）发给 WorkBuddy，它会帮你写好适配器接进去。

## 第二步：加载 Chrome 浏览器扩展

在 Chrome 地址栏输入 `chrome://extensions`，打开右上角「开发者模式」，点「加载已解压的扩展程序」，选中 JourneyForge-Local 里的 `extension/dist/chrome-mv3` 文件夹，完成。

> 安装失败大概率是网络访问不了 GitHub，换个网络环境或配好代理再试。

03

三步上手：从录屏到蒸馏到调用

整个使用逻辑就三步：**亲手做一遍 → 自动蒸馏 → 一句话调用。**

## 第一步：录制（1分钟）

在浏览器右上角拼图图标里找到 Journey Forge Local 扩展，打开。

先填一个 **Task name**（就是你要生成的 Skill 的名字，比如“B站自动点赞”），点 **Start recording**，然后像平常一样，在浏览器里把这个任务亲手做一遍——搜索、点开、填表、点赞，你想让 Agent 以后怎么干，你就怎么演示。

演示完点 **Stop**，再点 **Upload**，录制完成。

> 不用录很久，象征性做两三遍就够。录的是「怎么做成这件事」，不是「做了多少件事」。

## 第二步：蒸馏（自动进行）

回到 WorkBuddy，告诉它“录制完成，已上传”。

WorkBuddy 会去读取你上传的轨迹，交给大模型清洗、蒸馏，几分钟内生成一份完整的 Skill，装进 Agent 的技能库。

## 第三步：调用（以后随时）

下次你只要说一句话——“用 B 站自动点赞的 Skill，帮我把这个搜索页的 AI 视频都点了赞”，Agent 就会照着 Skill 的步骤执行，不用你再教一遍。

04

三个实战案例，直接上手

## 案例一：B站批量点赞

打开 Journey Forge Local，Task name 填“B站自动点赞”，开始录制后在 B 站搜索“AI 视频”，挨个点开视频并点赞，然后停止、上传。

蒸馏成 Skill 后，以后你只需说一句“帮我把搜索结果里的 AI 视频都点了赞”，Agent 就会自动搜索、逐条点开、点赞；遇到需要登录的页面，则由浏览器会话现场处理。

## 案例二：订房网站找性价比最高的民宿

官方论文演示过一个真实案例：在一家订房网站输入时间、地点、人数，按评分和评分数量筛选，排序找出最优选项。

这种任务看起来“简单”，小模型却经常栽跟头——要么不知道怎么用网站的筛选功能，要么干脆幻觉编造一个结果。而人做一遍、蒸馏成技能卡之后，小模型照着就能稳定完成：先写基本信息，再逐项应用筛选器，最后输出可人工核查的版本。

## 案例三：每周重复的高频报表下载

如果你每周都要进某个 SaaS 后台，按月份点击导出报表——这种“固定流程 + 登录 + 逐页点击”的活，正是传统自动化最烦的。

在浏览器里演示一遍「打开报表页 → 选月份 → 点导出 → 下载」，蒸馏成 Skill。以后每周一句话，Agent 自己进后台、点导出、存文件，你只管验收。

一个朴素的标准：**但凡你每周手动重复做一遍的浏览器操作，都值得花 5 分钟录一遍，蒸馏成一个永久 Skill。**

05

行动指南：5 分钟让 Agent 学会干活

现在花 5 分钟，把这件事落地。

**第一步（1分钟）**：把安装指令发给 WorkBuddy，让它装好 Browser-BC。

**第二步（1分钟）**：配置好模型 API，加载好 Chrome 扩展。

**第三步（2分钟）**：挑一个你每天都要重复的浏览器操作，打开 Journey Forge Local，录一遍，上传。

**第四步（1分钟）**：回到 WorkBuddy，让 Skill 生成，然后用一句话验证它能不能跑通。

几个提醒：

◆ 如果录制出来的 Skill 运行不理想，大概率是当前模型蒸馏质量一般，**换个更强的大模型（比如 GLM-5.2、Kimi K3）重新录一遍** 通常就好了。

◆ Skill 里不会夹带你录屏时的隐私内容（账号、密码、具体数据），清洗阶段会自动剥离。

◆ 录的是「门道」不是「脚本」，网站改版也不怕，Agent 会对着新页面举一反三。

从今天起，教 Agent 新技能不再靠“说”，而靠“做”。

**你亲手做一遍，就是最好的 Skill。**
