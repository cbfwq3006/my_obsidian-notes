# 2026-08-12_甲木未来派_公众号排版 Skill 初步提炼

> 本页仅为外部知识的初步提炼，尚未与稳定知识区整合。原始资料见：[[00 临时箱/开源一个排版 Skill｜彻底解决公众号排版难题（建议收藏！）]]

## 一、来源概况

- 来源：微信公众号「甲木未来派」
- 作者：甲木 Zuiyn
- 文章发布时间：2026-07-07 08:18
- 主题：开源 `gzh-design-skill`，将公众号排版经验封装为可由 AI Agent 执行的 Skill。
- 核心主张：把审美、组件、规则和校验流程系统化，使文章能够稳定生成适合复制到微信公众号编辑器的 HTML。
- 文中提到的开源项目：`isjiamu/gzh-design-skill`。项目地址和当前版本状态尚需实际核验。

## 二、关键事实

- 文章称该 Skill 支持 Markdown 到公众号 HTML 的转换，目标是复制粘贴到公众号编辑器后尽量不丢格式。
- 文章称生成结果使用内联样式，避免公众号编辑器对 `style` 标签、`script`、外部字体等内容的过滤问题。
- 项目按主题、组件和映射规则组织排版，而不是只提供一次性模板。
- 文中介绍了 6 套预设主题；每套主题包含组件库、色值、标题结构、正文标记、引用块、图片样式和文章类型配方。
- 文章称支持通过文字描述或参考图生成新的主题和组件库。
- 文章介绍两道校验：
  - `component_lint.py`：检查组件库中的平台禁用写法、`white-space:pre` 等潜在问题。
  - `validate_gzh_html.py`：检查最终 HTML 中的禁用标签、文字包裹和半角标点等问题。
- 文章称支持 WorkBuddy、TraeWork、QoderWork、Dumate、KimiWork 等 Agent 平台；兼容范围尚需逐一验证。
- 使用方式是先让 Agent 安装 Skill，再用类似“用摸鱼绿把这篇文章进行公众号排版：article.md”的指令触发。
- Markdown 是作者认为最稳定的输入格式；其他格式会先做格式归一化。
- 图片、GIF、视频等素材可以先生成“待补素材”占位板块，但长期图床和上传问题仍需用户自行解决。

## 三、核心观点

### 1. 排版属于内容表达的一部分

作者认为，用户注意力越来越受到图像和视觉形式训练，纯文字阅读要求读者主动建立结构、判断重点。更清晰的层级、图文组织和视觉呈现，可以降低阅读负担，提高继续阅读的意愿。

### 2. 真正的问题是工作流复用

一次性模板只能解决单篇文章的样式问题，不能解决每篇文章都要重复处理标题编号、引言卡、关键词强调、图片/GIF、代码块、Prompt 和命令行格式等工作流问题。

### 3. 约束是稳定输出的基础

先明确主题、组件和映射规则，再让 Agent 执行，可以把审美判断转化为可重复的生产规则。文章将“约束”视为保证输出下限的机制。

### 4. 组件化比单纯配色更重要

一个可复用主题不是一张封面图，而是一套覆盖封面、章节标题、正文、引用、提示卡、图片、GIF、代码块、表格、FAQ、作者信息和结尾互动区的排版系统。

### 5. 模型负责理解，脚本负责守红线

对能够确定的规范，不让模型自行猜测，而是交给脚本检查。通过“组件库校验 + 最终产物校验”，把“看起来没问题”转化为“通过了明确的规则检查”。

### 6. Skill 可以成为产品化经验载体

作者认为 Prompt、Skill 的价值都来自对具体场景的理解、经验压缩和试错成本降低；可维护、可扩展、可验证且能稳定解决实际需求的 Skill，具备合作或商业化可能。

## 四、可复用方法

### 方法 A：把审美经验拆成执行系统

1. 提取视觉偏好：主色、背景色、正文色、强调色、装饰色。
2. 明确版式变量：字体倾向、圆角、阴影、信息密度、标题结构、卡片形式、分割方式。
3. 将版式拆为组件：封面、标题、段落、引用、提示卡、图片、GIF、代码块、表格、FAQ、作者信息、结尾区。
4. 建立主题索引和映射规则。
5. 通过示例文章测试主题覆盖范围。
6. 固化为可反复调用的主题库。

### 方法 B：为素材保留接口

- 在原文中用“插入：某素材”的方式标注待补内容。
- 排版时生成明确的占位板块。
- 后续拿到图片、视频、GIF 或成果图后再替换。
- 将“内容结构”和“素材上传”拆成两个步骤，避免因图床问题阻塞排版。

### 方法 C：建立双重质量门

- 源头门：检查组件库是否含平台禁用写法或容易导致展示异常的写法。
- 产物门：检查最终 HTML 是否符合目标平台的标签、包裹和标点规范。
- 将可判定规则脚本化，将模型保留在内容理解和风格选择等需要判断的环节。

### 方法 D：优先结构化输入

- 正式写作优先使用 Markdown。
- 对 Word、纯文本等其他格式，先进行格式归一化。
- 排版指令包含主题名称和输入文件路径，减少 Agent 对任务边界的猜测。

## 五、可迁移到本知识库的启发

- 对公众号、通知、汇报、教程等重复性内容，可以研究“内容结构 + 表达组件 + 平台约束 + 自动校验”的 Skill 化方式。
- 若要把个人材料风格交给 Agent 执行，应先建立组件库、风格变量、适用场景和禁用规则，而不是只保存一条长 Prompt。
- 对正式输出，质量控制可以拆成“输入材料检查、结构检查、格式检查、平台产物检查”四类门槛。
- 适合进一步研究 Agent Harness：把模型不能稳定判断的硬约束转成脚本、清单或验证器。
- 这篇文章可作为“AI 工作流产品化”“Skill 工程化”“公众号内容生产”的案例来源。
