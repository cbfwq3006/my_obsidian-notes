# obsidian-wechat-summary

## 核心定位

把零散的微信群聊记录提炼成结构化、可扫读的简报，存入用户已有的来源资料系统，不强制创建 `sources/`。

**数据来源**：本技能调用本地 `wx-cli`（`wx` 命令）读取微信本地数据。wx-cli 不是 Obsidian CC 内置的——它通过扫描微信进程内存获取解密密钥、解密本地数据库，是逆向工程手段，**需要用户自行安装并初始化**。本技能只负责读取数据和生成摘要，不负责安装 wx-cli。

## 触发条件

- 用户说"总结一下 XX 群最近的聊天""XX 群聊了什么""群聊精华""群聊摘要"。
- 用户提到一个微信群名 + 时间范围，想了解群里的讨论。

## 必读

1. 先读 `.obsidian-cc/knowledge-map.md`（若存在）；“来源资料”必须映射到 folder 才能自动存档，把它记为 `<SOURCE_DIR>`。只有 tag / Property / Base、未映射或映射损坏时，先请用户选择具体文件夹。
2. 读取 KnowledgeMap 指向的 profile/style context；托管旧布局才回退到根目录同名文件。
3. 不写 KnowledgeMap 标记为只读的材料；长期知识只进入统一审核中心。

## 步骤

### Step 0：环境检查（wx-cli 前置依赖）

先确认 `wx` 命令可用——这是**阻塞步骤**，没有 wx-cli 后面全部做不了：

```bash
command -v wx && wx --version 2>/dev/null && echo "WX_OK" || echo "WX_MISSING"
```

- **`WX_OK`**：继续 Step 1。
- **`WX_MISSING`**：**立刻停下来，不要尝试安装**，告诉用户：

> 本技能需要 wx-cli（一个读取微信本地数据的命令行工具）。请先安装并初始化：
>
> **安装**：`npm install -g @jackwener/wx-cli`
>
> **初始化**（macOS 需先对微信做 ad-hoc 签名，详见 wx-cli 文档）：
> ```bash
> sudo wx init   # 需要微信正在运行
> ```
>
> 安装完成后验证：`wx sessions` 能看到最近会话即表示就绪。
>
> ⚠️ wx-cli 通过扫描微信进程内存来获取数据解密密钥，属于逆向工程手段，仅用于读取你自己的微信数据。macOS 上需要对微信重签名（`codesign --force --deep --sign - /Applications/WeChat.app`），详见 [wx-cli 文档](https://github.com/jackwener/wx-cli)。
>
> 安装好后重新跟我说"总结群聊"即可。

到此为止，不继续执行任何后续步骤。

### Step 1：解析用户的请求

从用户消息中提取：

- **群名**（或部分名称，用于模糊匹配）
- **时间范围** —— 灵活解释：
  - "最近 1 天" / "今天" / "last 24 hours" → 1 天
  - "最近 3 天" → 3 天
  - "最近 7 天" / "这周" → 7 天
  - "最近一个月" → 30 天
  - "某天"（如"3 月 5 号"）→ 特定日期
  - 未指定 → 默认取最近 24 小时
- 将相对范围转成绝对日期：`--since YYYY-MM-DD --until YYYY-MM-DD`

### Step 2：找到目标群

```bash
wx contacts --query "<群名>" --json
```

从结果中筛选 `username` 以 `@chatroom` 结尾的条目（群聊标识）。

- **唯一匹配**：继续。
- **多个匹配**：列出来让用户选（用编号，等用户回复）。
- **无匹配**：尝试 `wx sessions --json` 搜一遍；仍无则告诉用户找不到这个群。

### Step 3：拉取群聊消息

**始终输出到临时文件**（大群聊消息量大，直接读会烧上下文）：

```bash
wx history "<群名或群ID>" --since YYYY-MM-DD --until YYYY-MM-DD -n 5000 --json > "$TMPDIR/wx-messages.json"
```

检查拉取结果：

```bash
jq 'length' "$TMPDIR/wx-messages.json"   # 消息总数
```

- **0 条**：告诉用户这个时间范围内没有消息。
- **> 500 条**：建议分段（每 3 天一份）后再合并，避免单次摘要质量下降——先跟用户确认是否接受分段。
- 之后用 `jq` 或 `Read`（带 offset/limit）分批读取，**不要一次性全部读入上下文**。

### Step 4：理解消息结构

`wx history --json` 返回消息对象数组，关注这些字段（容错缺失字段）：

- `from_wxid` / `from_nickname` —— 发送者标识 / 昵称
- `content` —— 文本内容。特殊占位符：`[图片]`（无法解码，跳过）、`[表情]`（跳过）、`[视频]`/`[文件]`（跳过，除非有人讨论）、`[链接] <标题>`（标题即信息，引用并标注分享者）、`[系统] ...revokemsg`（撤回，排除）
- `timestamp` —— 转成 `MM-DD HH:MM` 显示
- `quote_id` / `reply_to`（如有）—— 引用/回复链，用于归属判断

### Step 5：构建话题骨架（第一轮）

按时间顺序读完所有消息，列出每个独立讨论话题。内部工作格式（不写入最终文件）：

```
== 话题清单（共 N 条消息）==
1. [HH:MM-HH:MM] 话题名称（参与者：A, B, C）— 一句话概括（锚点：id 发言人:"原话片段"）
2. ...
== 发言统计 ==
1. XXX — N 条  2. YYY — N 条  ...
```

话题划分原则：
- 话题切换信号：时间间隔 > 30 分钟、参与者变化、内容跳转。
- 2+ 人参与或有实质内容才算话题；纯表情斗图不算。
- **严格归属**：每个话题记录"谁说了什么"，用锚点 ID + 原话片段（从原始消息**逐字复制**，不要改写），防止张冠李戴。

### Step 6：展开并撰写摘要（第二轮）

对骨架中每个话题，回到锚点 ID 展开成完整内容。然后撰写简报。**开头概览最后写**（基于已完成的正文，确保引言准确）。

**图片处理**：wx-cli 不解码聊天图片。如果某个话题严重依赖图片且无文字说明，在摘要里如实说"此处讨论围绕一张图片展开，图片内容未知"，**不要编造视觉内容**。

**消息量很大时**：用 `jq` 做轻量骨架扫描，再对关键话题精读原始消息：

```bash
jq '[.[] | {id, from_nickname, timestamp, content: (.content | .[0:60])}]' "$TMPDIR/wx-messages.json"
```

### Step 7：归因校验（第三轮，不可跳过）

对摘要里每一处直接引用（引号内）和"X 说 / X 分享"归属，grep 原始消息文件确认：

```bash
grep "原话片段" "$TMPDIR/wx-messages.json"
```

- 引用找不到 → 改写偏差或记忆虚构，恢复原文措辞或删掉。
- 引用找到但发送者不符 → 归属错误，改对名字。
- 修正后确认无误，再继续。

### Step 8：写入已映射的来源位置

仅在 `<SOURCE_DIR>` 已明确时写入 `<SOURCE_DIR>/wechat-summaries/<群名>-<YYYY-MM-DD>.md`（日期范围用 `YYYY-MM-DD_YYYY-MM-DD`）。群名做 sanitize：`/ \ : * ? " < > |` 和控制字符替换为 `_`。同日同名已存在则加 `-2`、`-3`。未映射时不要创建目录，先问用户。

文件骨架：

```md
---
source: wx-cli 本地微信数据
group: <群名>
group_id: <群ID>
date_range: <YYYY-MM-DD> 或 <YYYY-MM-DD ~ YYYY-MM-DD>
generated_at: <ISO 时间>
message_count: <消息总数>
generated_by: obsidian-wechat-summary
---

# <群名> 群聊精华 · <日期或范围>

## 概览

<2-3 句话：这个时间段群里整体聊了什么、氛围如何、有什么值得注意的>

## 话题

### 1. <话题名>

<参与者> · <时间段>

<话题展开：谁说了什么，关键信息，引用原话>

### 2. <话题名>

...

## 发言统计

| 排名 | 群友 | 消息数 |
|------|------|--------|
| 1 | XXX | N |
| ... | ... | ... |

（共 N 位群友发言，N 条消息）
```

## 输出

- 主产出：KnowledgeMap 已映射来源目录下的 `wechat-summaries/<群名>-<日期>.md`。
- 结束时用一两句话告诉用户：存到了哪个文件、覆盖了多少消息、有几个话题。
- 如果群聊中有值得长期记住的稳定事实，输出带聊天来源摘录、时间状态和置信度的 `occ-knowledge-candidates` 协议，交给桌面知识审核中心；目标未映射就留空。

## 禁区

- ❌ 不创建固定 `raw/`、`sources/` 或 `memory/inbox/`，不改 KnowledgeMap 的只读范围。
- ❌ 不直接修改长期知识；候选只进入统一审核中心。
- ❌ 不编造图片内容——图片是黑盒，如实标注"图片内容未知"。
- ❌ 不把推测当事实——Agent 判断一律标 `(Agent 判断)`。
- ❌ 不自动安装 wx-cli、不替用户跑 `sudo`、不替用户重签名微信。

## 常见卡点

- **`wx` 命令不存在**：走 Step 0 的安装引导，不绕过。
- **`wx init` 未完成**：`wx sessions` 返回空或报错"keys not found"。告诉用户：需要保持微信运行，然后 `sudo wx init`（macOS 还需先重签名）。
- **`wx history` 突然返回空（微信重启后）**：密钥可能过期，让用户重新 `sudo wx init --force`。
- **群名匹配不到**：群可能在最近会话里没出现。让用户先在微信里点开那个群发条消息，让 wx-cli 能发现它，再试。
- **消息量过大（>500 条）**：建议分段生成（每 3 天一份），单次消化质量更好。
- **macOS 报"无法扫描微信内存"**：微信更新后签名失效，需重新 `codesign --force --deep --sign - /Applications/WeChat.app`。
