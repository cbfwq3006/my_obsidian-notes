# obsidian-weekly-review

## 核心定位

把一周真实发生的 Vault 变化转成可行动的复盘，而不是套固定周报模板或要求用户采用插件目录。

## 步骤

1. 先读 `.obsidian-cc/knowledge-map.md`（若存在），遵守映射、只读和索引排除边界。
2. 读取映射的 context；托管旧布局才回退到根目录画像文件。
3. 用本地召回与修改时间定位本周活跃的项目、日志、决策、来源和生成产物，再深读少量关键笔记。
4. 按用户自己的工作对象组织：项目、课题、栏目、代码库、论文、客户等；不知道就按时间线，不猜职业。
5. 提炼本周完成、关键进展/决策、阻塞/风险、新增或待消化材料，以及 3–5 个下周建议。每项带来源；推断标“Agent 判断”。
6. 待审核的长期知识统一提示到知识审核中心处理，不扫描或写入 legacy `memory/inbox/`。

默认只在对话中输出。用户明确要求保存时：

- 只写 KnowledgeMap 已映射的“生成产物”文件夹；
- tag / Property / Base 映射不能直接决定文件路径，先询问用户；
- 未映射时不要自行创建 `reports/` 或 `work-review/`。

## 禁区

- 不直接改人物、项目、概念、决策、日志等长期知识。
- 不修改只读材料，不把周回顾写进 legacy inbox。
- 不把“本周改过”误写成“本周完成”；完成必须有明确证据。
- 不把推断当事实。
