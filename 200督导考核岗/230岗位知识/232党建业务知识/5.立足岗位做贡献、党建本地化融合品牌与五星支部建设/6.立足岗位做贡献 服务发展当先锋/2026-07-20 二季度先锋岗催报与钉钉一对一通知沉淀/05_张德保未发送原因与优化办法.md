# 张德保未发送原因与优化办法

## 一、现象

2026年7月20日二季度党员先锋岗通知批量发送时，张德保未发送成功。

人员表信息：

- 部门：机动通信局
- 姓名：张德保
- 手机号：15639102777

后续截图显示，钉钉客户端中可以打开张德保单聊，并且已能人工发送消息。

## 二、原因判断

这不是“张德保不在钉钉”，而是 DWS 当前接口没有拿到可用于发送的人员标识。

已验证：

| 查询方式 | 结果 |
| --- | --- |
| `contact user search-mobile --mobile 15639102777` | 返回空 |
| `contact user search --query 张德保` | 返回空 |
| `aisearch person --keyword 张德保 --dimension name` | 返回空 |
| `aisearch person --keyword 15639102777 --dimension phone` | 返回空 |

截图中张德保的组织路径显示为“中国联合网络通信集团有限公司-省分公司-中国联通河南省分公司-河南省公司本部-河南机动通信局……”，与当前 DWS 登录组织“焦作市分公司”的通讯录接口可见范围可能不一致。

因此，钉钉客户端可以单聊，不代表 DWS 的 `contact` 或 `aisearch` 接口能查到 `userId`。

## 三、优化办法

### 1. 人员表增加兜底列

建议党务人员表在“部门、姓名、联系电话”后增加：

| 字段 | 用途 |
| --- | --- |
| `userId` | DWS 可直接用 `--user` 发送 |
| `openDingTalkId` | DWS 可直接用 `--open-dingtalk-id` 发送 |
| `备注` | 记录跨组织、人工确认、手机号异常等情况 |

### 2. 脚本发送顺序调整

后续脚本按以下顺序找人：

1. 人员表已有 `userId`，直接用 `--user`。
2. 人员表已有 `openDingTalkId`，直接用 `--open-dingtalk-id`。
3. 没有人工标识，再用手机号查。
4. 手机号查不到，再用姓名查。
5. 仍查不到或结果不唯一，列入人工核实名单，不发送。

### 3. 避免“只发标题”

普通通知消息只传正文：

```powershell
dws.cmd chat message send --user <userId> --text "通知标题`n`n通知正文" --format json
```

不要同时传：

```powershell
--title "标题" --text "正文"
```

标题应放在正文第一行。

### 4. 发送前先自测

每次批量发送前，先给本人发送一条完整测试消息。本人确认正文完整显示后，再批量发送。

## 四、张德保后续处理建议

1. 在钉钉客户端确认张德保的手机号是否仍为 `15639102777`。
2. 如能获取其 `userId` 或 `openDingTalkId`，补录到人员表。
3. 后续批量发送脚本会优先使用补录标识，不再依赖通讯录搜索。
