# 外部知识进入规则

> 适用对象：从微信、网页、文章、截图、录音、文件、聊天记录等外部渠道进入 Obsidian 的新知识。

## 总原则

外部知识先进入 `00 临时箱`，先保全原始信息，再提炼、比对、确认、整合。没有经过确认前，不直接混入 `wiki/`、`01 通用体系/`、`02 角色体系/` 等稳定知识区。

## 进入流程

1. 先存入 `00 临时箱`。
   - 新建 Markdown 笔记，文件名优先使用 `YYYY-MM-DD_来源_主题.md`。
   - 笔记开头写明来源、进入时间、原始材料类型、处理状态。
   - 原文、截图 OCR、录音转写、链接摘要等先作为原始材料保存，不覆盖、不删减。

2. 自动同步，不再要求用户手动点 Obsidian 同步按钮。
   - Codex 或 Claudian 处理外部知识后，应主动执行本库同步动作。
   - 本库使用 Git/GitHub 同步时，优先执行 `git status`、`git add`、`git commit`、`git push`。
   - 如果 Obsidian Git 插件正在运行，可使用插件自动备份；但不能把“等用户手动点击同步”作为默认步骤。
   - 如果同步失败，必须明确告诉用户失败原因、未同步文件范围和下一步处理建议。

3. 对内容进行提炼。
   - 提炼关键事实、核心观点、可复用方法、案例、问题、待验证判断。
   - 标明哪些是原文事实，哪些是推断，哪些是我的理解。
   - 尽量把可复用内容沉淀为 SOP、判断标准、清单、模型或问题框架。

4. 结合已有知识库内容进行比对。
   - 先查 `wiki/index.md`、`知识体系总纲.md`、相关 `01 通用体系/`、`02 角色体系/`、`200督导考核岗/` 内容。
   - 找出可连接的旧笔记、相同主题、相反观点、可补充案例和可能重复内容。
   - 使用 Obsidian 双链列出建议关联页面。

5. 整合前必须向用户确认。
   - 在真正写入稳定知识区前，先给出“整合建议清单”。
   - 说明准备写入哪些位置、更新哪些旧笔记、保留哪些原始材料、是否需要新建概念页或 SOP 页。
   - 用户确认后再执行整合；用户未确认时，只保留在 `00 临时箱`。

6. 整合后收尾。
   - 更新相关索引、双链、日志或任务记录。
   - 原临时笔记不删除；可移动到 `00 临时箱/已归档`，或在原笔记中标记 `status: integrated`。
   - 整合完成后再次执行同步，并报告同步结果。
