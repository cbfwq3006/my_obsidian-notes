一个 Agent 能不能真正干活，不只取决于模型本身，还取决于它有没有清晰的工作方法，有没有长期记忆，有没有检索能力，有没有理解项目结构的能力，有没有输出内容时贴近人的表达能力。

如果你只是裸跑 Codex，它很容易变成一个临时工。

你每次都要重新交代背景，每次都要提醒它先思考，每次都要告诉它去哪里查资料，每次都要纠正它写出来的内容太像 AI。

但如果你给它装上一些关键 Skill，它就不只是一个会回复问题的工具，而更像一个有方法、有记忆、有搜索能力、有项目视野的助手。

下面这 6 个 Skill，是我目前觉得 Codex 最值得优先装的一组。

## 第一个，Superpowers

  

Superpowers 解决的是一个最基础的问题：让 Agent 不要一上来就瞎干。

很多时候我们让 AI 写代码，最大的问题不是它不会写，是它太急着写。

你给它一个需求，它马上开始改文件。

你给它一个 bug，它马上猜原因。

你让它优化项目，它马上开始动代码。

表面上看很积极，实际上很危险。

因为真实项目里，最怕的不是慢，是方向错了还干得很快。

Superpowers 的价值就在这里。

它会让 Agent 先思考，先写计划，先拆任务，最好还能按测试开发的方式一步步推进，最后再自查自己改了什么。

这听起来好像只是一个流程约束，但对真实工作非常重要。

因为一个靠谱的 AI 助手，不应该只是会执行，它应该先理解问题，再决定怎么执行。

这就像你找一个人合作，你真正放心的不是他手速快，是他知道什么时候该先问清楚，什么时候该先列计划，什么时候该先验证。

所以如果你经常用 Codex 写代码，我觉得 Superpowers 是很值得优先装的。

它不是让 Agent 变得更炫，要让 Agent 变得更稳。

第二个是 OpenAI 官方插件。

这里要稍微解释一下，严格来说，它们本身是官方插件能力包，而在 Codex 里又会以 Skill 的形式被调用。

所以你说它是插件也对，说它是插件里的 Skill 也对。

普通用户不用太纠结这个概念。

重要的是它能把 Codex 从单纯写代码，扩展到更多真实工作场景。

比如数据分析、销售、投研、PPT、文档、表格、网页、浏览器操作。

这些能力单独看，好像只是工具集合。

但如果放进工作流里，意义就不一样了。

你不再是让 AI 只回答问题，是让它真的参与到你的工作交付里。

比如你要分析一份表格，它可以读数据、整理结论、生成图表。

比如你要做一个方案，它可以帮你整理文档、生成 PPT 结构。

比如你要搭一个小页面，它可以写前端、预览、调试、再部署。

以前这些事要在很多软件之间来回切换，现在可以让 Agent 串起来。

这才是官方插件真正有价值的地方。

不是多了几个功能，是让 AI 从聊天框走向真实生产环境。

官方插件这类能力，就是把系统打通的一块关键拼图。

第三个是 claude-mem。

它解决的是长期记忆问题。

这个问题很多人一开始不会特别在意，但用久了就会很痛。

你会发现，每次开一个新对话，都要重新解释项目背景。

这个项目是干什么的，之前改过哪些地方，哪些规则不能碰，用户偏好是什么，代码结构是什么，写作风格是什么。

讲一两次还行，讲多了就很烦。

而且更麻烦的是，有些上下文你自己也不一定能每次都讲完整。

这时候 Agent 就容易做出看似合理但不符合项目历史的判断。

claude-mem 的价值，就是给 Agent 加一层长期记忆。

它可以把重要背景沉淀下来，让 Agent 不用每次都从零认识你、认识项目、认识当前工作流。

这个能力对我这种用 Obsidian 搭知识库的人，其实特别有共鸣。

因为我一直觉得，AI 真正要变成自己的助手，前提是它要认识你。

它要知道你是谁，你在做什么，你的长期主线是什么，你的表达风格是什么，你做过哪些项目，踩过哪些坑。

没有记忆的 AI，只能做一次性回答。

有记忆的 AI，才可能变成长期合作者。

所以 claude-mem 不是一个简单的功能增强，它更像是给 Agent 装上了个人上下文。

第四个是 Agent-Reach。

它解决的是搜索和调研问题。

现在很多 AI 工具都会说自己能联网，但真正做内容、做产品、做研究的时候，光能搜网页是不够的。

因为很多有价值的信息不只在普通网页里。

它可能在 X，也可能在 Reddit，也可能在 YouTube、小红书、B 站、公众号里。

尤其是做 AI 工具、内容选题、行业观察的时候，如果只看搜索引擎，信息会很慢，也很扁平。

Agent-Reach 的价值，就是让 Agent 有能力去更广的信息源里找线索。

比如你想知道一个工具是不是真的火了，不能只看官网怎么说。

你还要看开发者怎么讨论，普通用户怎么吐槽，视频平台有没有教程，小红书有没有使用场景，公众号有没有深度分析。

这些信息拼在一起，才更接近真实世界。

这也是我现在做内容时越来越重视的一点。

不要只搬运新闻，不要只看官方通稿，要看到真实用户在怎么用、怎么骂、怎么夸、怎么踩坑。

Agent-Reach 这种 Skill，本质上是在帮 Agent 打开外部世界。

没有它，Agent 很容易困在已有上下文里。

有了它，Agent 才能把你的知识库和外部信息连接起来。

第五个是 GitNexus。

它解决的是大项目理解问题。

如果你接手过老项目，应该会知道那种感觉。

打开代码仓库之后，文件很多，目录很多，模块之间互相调用。

你不知道入口在哪里，不知道核心逻辑在哪里，也不知道哪些地方能改，哪些地方不能乱动。

这时候让 AI 直接改代码，其实风险很高。

因为它可能只看到局部文件，却没有看到整个项目的结构。

GitNexus 的价值，就是把大项目变成代码图谱。

它可以帮助 Agent 理解项目结构、模块关系、调用链路，让它不只是看一段代码，而是看到整个系统。

这对真实开发非常关键。

因为写代码最难的地方，往往不是某一行怎么写，要理解一个系统为什么这样组织。

一个变量为什么存在，一个接口为什么这样设计，一个模块为什么不能随便拆，这些都需要结构视野。

如果没有代码图谱，Agent 很容易变成局部聪明，全局糊涂。

而 GitNexus 的意义，就是尽量让 Agent 从局部执行者，升级成系统理解者。

对大项目、老项目、多人项目来说，这个能力非常重要。

第六个是 Humanizer-zh。

它解决的是中文表达里的 AI 味问题。

这个问题我自己特别有感触。

因为现在很多 AI 写出来的中文，看起来很完整，也很顺滑，但就是不像人写的。

它喜欢用过度工整的结构，喜欢写很多套话，喜欢把每件事都说得很圆满。

看上去没有错，但没有真实感。

尤其是做公众号、朋友圈、个人 IP 内容的时候，这种 AI 味会很伤。

因为用户不是只看信息，他们也在感受你这个人。

如果一篇文章太像模板，太像总结稿，太像平台说明书，读者很快就会划走。

Humanizer-zh 的价值，就是专门处理中文里的 AI 痕迹。

它可以帮你把过度机械的表达改得更自然，把太标准化的句子改得更像真人，把太满的结论改得更有呼吸感。

当然，我觉得这里也不能完全依赖工具。

真正去 AI 味的核心，还是要有自己的真实经历、真实判断、真实语气。

工具只能帮你修表面，人味来自你自己。

但如果你已经有素材、有观点、有经历，只是 AI 写出来太硬，那 Humanizer-zh 就很有用。

它可以让你的内容更接近真实表达，而不是一眼看上去就是机器生成。

## 这 6 个 Skill，其实对应 6 种真实能力

  

如果把这 6 个 Skill 放在一起看，你会发现它们不是简单的工具清单。

它们其实对应 Agent 进入真实工作流需要的 6 种能力。

Superpowers 对应的是思考和计划能力。

OpenAI 官方插件对应的是连接各种工作场景的能力。

claude-mem 对应的是长期记忆和上下文沉淀能力。

Agent-Reach 对应的是外部调研和信息获取能力。

GitNexus 对应的是大项目结构理解能力。

Humanizer-zh 对应的是中文表达和内容优化能力。

这 6 个能力串起来，Agent 才更像一个完整的工作助手。

它能先思考，再执行。

能记住你，不用每次重新认识你。

能出去查资料，不只困在当前对话里。

能理解项目结构，不只盯着局部代码。

能接入文档、表格、PPT、网页这些真实交付场景。

还能把内容改得更像人说的话。

这才是我觉得 Skill 真正有意思的地方。

不是多装几个插件，不是多几个花哨功能，你要开始给 Agent 搭一套工作系统。
